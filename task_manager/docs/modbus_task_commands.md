# task_manager Modbus 任务发送命令指南

## 1. 连接参数

- 目标地址：`192.168.1.123`
- TCP 端口：`12000`
- Modbus 从站地址：`1`
- 数据类型：保持寄存器，16 位无符号整数（`mbpoll -t 4`）
- 单次请求：`mbpoll -1`

通用写寄存器命令：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r <mbpoll寄存器号> -1 <写入值>
```

通用读寄存器命令：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r <mbpoll寄存器号> -c 1 -1
```

YAML 寄存器地址与 `mbpoll -r` 的换算关系：

```text
mbpoll寄存器号 = YAML寄存器地址 - 40000
```

例如：YAML 中 `40001` 对应 `-r 1`，`50001` 对应 `-r 10001`。

## 2. 当前任务命令表

当前任务来自 `config/task_config.yaml`。

| 任务 | 动作 | 触发寄存器 | 状态寄存器 | mbpoll 触发号 | mbpoll 状态号 |
|---|---|---:|---:|---:|---:|
| `move_box` | 左、右机械臂关节运动 | 40001 | 50001 | 1 | 10001 |
| `control_suck_example` | 左吸盘控制 | 40002 | 50002 | 2 | 10002 |

### 2.1 发送 `move_box`

> 警告：该任务会触发真实双臂运动。当前配置的两臂首关节目标均为
> `90.0`，注释单位却是 `rad`。必须先确认该数值和单位正确、人员已离开运动区域，
> 并保证急停可用，才能执行以下命令。

触发任务：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 1 -1 1
```

读取任务状态：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 10001 -c 1 -1
```

需要手动清除触发位时：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 1 -1 0
```

### 2.2 发送 `control_suck_example`

触发任务：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 2 -1 1
```

读取任务状态：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 10002 -c 1 -1
```

需要手动清除触发位时：

```bash
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 2 -1 0
```

## 3. 状态值

| 状态值 | 含义 |
|---:|---|
| `0` | 尚未运行或寄存器初始值 |
| `1` | 任务运行中 |
| `2` | 任务执行成功 |
| `3` | 任务执行失败 |

任务正常完成后，任务管理器会自动把对应触发寄存器恢复为 `0`。

## 4. 推荐操作流程

1. 确认 `task_manager`、运动控制节点和安全节点均已正常启动。
2. 检查目标任务的 YAML 参数；机械臂任务必须确认单位、关节限位和现场安全。
3. 读取对应状态寄存器，确认没有任务处于运行状态。
4. 向触发寄存器写入 `1`。
5. 轮询状态寄存器，等待状态由 `1` 变为 `2` 或 `3`。
6. 只有当前任务结束后，才发送下一项任务。

持续查看 `move_box` 状态（每秒一次，按 `Ctrl+C` 退出）：

```bash
watch -n 1 'mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 10001 -c 1 -1'
```

## 5. 重要限制

- 任务仅在任务管理器处于 `IDLE` 状态时接受。
- 触发条件是寄存器值从 `0` 变为 `1`。如果任务因系统忙而被忽略，必须先写
  `0`，等待系统回到 `IDLE`，再写 `1`。
- 当前实现按“触发寄存器 + 10000”更新状态，因此配置必须满足
  `status_reg = trigger_reg + 10000`。
- 当前任务执行期间不要发送其他 Modbus 写请求；读状态寄存器不受此限制。
- 不要向状态寄存器写值，状态寄存器由任务管理器维护。
- `mbpoll` 每次使用 `-1` 建立一次短连接，符合当前 Modbus 服务端的连接处理方式。

## 6. 新增任务后的命令生成规则

若新增任务配置为：

```yaml
tasks:
  example_task:
    trigger_reg: 40003
    status_reg: 50003
```

对应命令为：

```bash
# 触发
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 3 -1 1

# 查询状态
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 10003 -c 1 -1

# 必要时清零触发位
mbpoll 192.168.1.123 -p 12000 -a 1 -t 4 -r 3 -1 0
```
