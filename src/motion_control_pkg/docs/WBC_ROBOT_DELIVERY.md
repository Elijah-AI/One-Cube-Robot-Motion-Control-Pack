## 默认不启用运动平衡控制

`wbc_static_com_enabled=false`、`wbc_dynamic_zmp_enabled=false`，保持兼容默认。
本次交付不自动修改 `/opt/onecube` 配置、不重启控制节点、不发送任何运动。
单纯编译成功并不意味着实机防倾覆控制已经启用。

静态模式须显式确认底盘静止、水平地面和四轮接触：
`wbc_stationary_horizontal_contact_confirmed=true`。这只是操作方确认，
不是由 URDF 或关节角检测出的接触事实。

机器人所有质量、惯量、支撑几何、关节名称和机械限位以 URDF 为准。
未知前后转向角由静态模式的保守边界覆盖；不能填假实时反馈。
动态 ZMP 模式要求完整、带时间戳、非假定的 q/v 状态，缺转向反馈时不得启用。
腿腰速度只能用带时间戳角度差分并滤波估计，不能仅从 URDF 获得。

## 应先进行的真机验证

1. 先确认实际 URDF / 工具和无额外负载；检查臂、腿腰、头部的关节名、弧度、
   时间戳、反馈频率和新鲜度，以及完整状态汇总话题 `/wbc/joint_states`。
2. 独立启动只读 `wbc_model_node`，核对静止 COM、支撑和缺失 / 超时状态。
   `launch/wbc_model.launch.py` 不启动实机驱动、不发送指令。
3. 人工确认硬件急停、稳定支撑、限速与监护，再另行授权低速小范围动作。

不是直接进行实机远伸、快速运动或倾覆边界实验。仿真已经暴露后仰腿部力矩
先于 COM 边界超限，以及外部推力下虚拟伺服大跟踪误差；尚无实机在线接触力
抗扰纠偏和完整力矩可行性保证。取消 30° 阈值不表示任意姿态可以执行。

## 构建和诊断

完整构建需要 `com_interfaces`、Pinocchio、Coal / OMPL、PCL、Ruckig 和
仓库现有厂商库。`cmake -DWBC_MODEL_ONLY=ON` 可单独构建模型 / 只读工具，
不需连接硬件，也不依赖 MuJoCo。

交付的可执行诊断工具为 `wbc_model_audit`、`wbc_zmp_audit`，以及只读观察器
`wbc_model_node`。详细构建 / 同步指纹和离线回归报告保存在仓库外的本次交付
目录，不作为机器人功能包的一部分。

`.136` 若已有运控进程在运行，使用独立 build / install 目录完成 `Release`
和 `-O2 -DNDEBUG` 编译；colcon 和 CMake 两层均限定一个任务。切换新安装前
需要明确停止旧节点并重新核对实际参数路径，本次交付不自动执行这一切换。
