## 三档避障

`MovePose.action`、`MoveJoints.action` 和任务 YAML 统一使用
**`uint8 enable_collision_check`**：

| 值 | 行为 |
| --- | --- |
| `0` | 关闭碰撞检查；关节限位、速度和控制器约束仍保留 |
| `1` | 只检查配置的机器人自碰撞对；不订阅、不安装外部点云 |
| `2` | 检查自碰撞和外部障碍；外部几何与机器人碰撞几何建立碰撞对 |

```yaml
params:
  enable_collision_check: 2
```

对应 Action 常量为 `COLLISION_DISABLED`、`COLLISION_SELF`、
`COLLISION_SELF_AND_ENVIRONMENT`。不再在 Action 中使用独立的
`enable_point_cloud_check` 布尔字段。

旧 YAML `false/true` 兼容映射为 `0/1`；旧 `true` 配合
`enable_point_cloud_check: true` 映射为 `2`。显式数字 `0/1/2` 始终优先，
其他值拒绝加载。仓库当前任务配置已改为数字。

模式 2 优先使用 `MovePose.env_point_cloud`；没有显式点云时从
`collision_pointcloud_topic` 读取 `SyncedRobotVision.camera_rgbd_pointcloud`。
默认话题为 `/fusion/synced_robot_vision`，与 develop 相机接口一致。
`MoveJoints` 通过同一话题取得点云。等待上限 2 秒；缺失、空云、无效 XYZ
或未知坐标系均报错，不退回仅自碰撞。显式点云须提供有效 `header.frame_id`。
模式 0/1 会忽略所附外部点云。

碰撞模式和临时场景在规划期间加锁，规划结束/失败后恢复，轨迹下发前释放。
单臂 MoveJoints、头部和下肢对已有轨迹采样点进行检查，碰撞则拒绝下发；
它们不会自动寻找绕行路径。双臂和已有 MoveP/MoveL/全身规划链继续使用
HHworkspace 的规划与采样检查。本次外部检查使用规划时取得的点云快照，
不是运动期间持续更新的动态避障。点云应表示可用的环境几何，包含机器人
自身或噪声时可能拒绝轨迹。

Action 类型发生变化，部署时必须一起重新生成接口并重编译运控、任务层及
相关客户端，避免使用旧安装目录的类型支持库。
