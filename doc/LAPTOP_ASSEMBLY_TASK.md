## 几何与姿态

所有视觉位姿必须已经是真实 `base_link` 位姿，且每次恰好一个目标。
这里不再施加相机到基座的变换。位置公式为：

```text
p_tcp = p_vision + R(q_vision) * translation
q_tcp = normalize(q_vision * rotation)
```

2026-09-30：三轮左右臂的放置接近、下降、松爪后侧移和上提共24个动作，
在 `vision_pose_offset` 中启用 `force_vertical_down: true`。先计算上式的映射姿态，
再将其TCP X轴投影到基座XY平面，保留该水平方向，同时将TCP Z轴强制对齐
`base_link -Z`。因此视觉roll/pitch不再带入放置TCP姿态；槽位平移仍使用原始
视觉完整姿态，`current_tcp_height`高度求交和视觉Z方向的下降/上提路径保持原公式。
该约束需要更新后的task_manager解析器和目标生成代码；旧程序不会执行此约束。
这里约束的是TCP目标：接近MoveP到达后，下降MoveL采用竖直TCP姿态；接近MoveP
中间的关节路径不承诺始终竖直，实物夹爪/工件竖直精度还依赖工具标定与夹持状态。
TCP X投影无法确定水平朝向、或frame_id不是base_link时拒绝目标，不静默回退。
下文左右旋转偏移用于确定水平朝向，随后应用上述竖直约束。

右臂放置接近、直线下降、松爪后MoveP和直线退出统一绕视觉局部 Z 轴旋转180°：
`q_new = q_vision * q_Z180 * q_offset_old`。因此将右臂放置的固定偏移从
`[0.7071067811865476, 0.7071067811865476, 0, 0]` 改为
`[0.7071067811865476, -0.7071067811865476, 0, 0]`（与乘积的整体取负等价）。
只改变 TCP 姿态，仍使用原视觉姿态计算位置，右臂固定腰部单臂 MoveP 到与当前TCP等高的槽上方，固定腰部 MoveL 下降到10 cm；松爪到200后MoveP沿视觉−Y移3 cm，再保持偏移后的Y以MoveL上提至20 cm。

`[0.7071067811865476, -0.7071067811865476, 0, 0]` 改为
`[0.7071067811865476, 0.7071067811865476, 0, 0]`，仍按同一公式计算。

### 抓取托盘的180度翻转修正

抓取检测目标 `rack`（内部缓存键 `rack`）的配置：

```yaml
canonical_y_direction: [-1, 0, 0]
canonical_y_min_alignment: 0.5
```

在 `expected_frame_id: base_link` 下，计算视觉局部 +Y 与基座 -X 的归一化点积。
点积为负时，右乘局部 Z 的 180° 旋转：`q_corrected = q_measured * [0,0,1,0]`。
点积为正时保留原旋转。两种情况均归一化四元数，位置、局部 Z 法向和倾斜不变。
点积绝对值小于 0.5 时，方向与参考轴偏离超过60度，检测动作报错，不继续生成抓取目标。

修正在视觉结果缓存前执行，槽位偏移和左右 TCP 对齐共用同一修正结果，
接近、下降、提起不会反复旋转或累计偏移。统一后的槽序仍沿局部 -Y，
左侧较小槽号的 TCP x 小于右侧较大槽号；不再根据原始视觉的正反朝向临时交换槽号。
四元数整体取反 `q -> -q` 不表示姿态翻转，不触发不同的物理修正。

此设置仅适用于当前以中心为原点、具有局部Z半周对称性的抓取托盘。
放置检测目标 `tray`（内部缓存键 `tray`）为右下角原点，保持原始位姿；其他任务默认不启用。
未消除任意倾斜、法向翻面或真实物体运动，也不能保证所有 IK 均可解。
手工直接发送 MovePose 的固定目标绕过此逻辑；要自动生效，需构建并运行更新后的 task_manager。

## 新增任务参数

- `vision_detect.params.result_key`：在同一 `action_sequence` 命名保存结果。
- `move_pose.params.vision_result_key`：只读取同名结果；缺失、失败或跨序列时直接失败，不回退到最近目标。
- `vision_pose_offset.translation_frame: vision`：平移沿视觉局部轴；缺省 `base` 保持旧任务基坐标偏移行为。
- `left_vision_pose_offset`、`right_vision_pose_offset`：双臂分别计算目标，必须成对给出，支持 `arm_id=2/7`。
- 单臂 `vision_pose_offset` 同时支持 `arm_id=0/1/5/6`。使用偏移时 `bound_size` 必须全零，防止重复平移。
- 任务开始/复位清空所有序列视觉缓存；先前任务的 `rack`/`tray` 不会带入下一轮。
- `move_joints.params.relative_position: true` 仅支持 `arm_id=4, joint_name: [body_joint]`。
  `position[0]` 是相对增量（rad）。任务客户端从 `/wbc/joint_states` 读取四个腰腿关节，
  生成既有四轴 LEG 绝对目标：腿部沿用反馈，J4 加增量，运控仍执行原有角度限位和碰撞检查。
  消息时间戳与本地接收时间均需在 250 ms 内，允许时钟前偏最多 50 ms；
  腰腿位置/速度需完整、唯一、有限，速度绝对值均不超过 0.01 rad/s。
  可用节点参数 `task_joint_state_topic` 或 ROS remap 指定反馈话题。
- `arm_id=4, joint_name: [body_joint], relative_position: false` 表示腰部绝对角目标，
  同样读取新鲜、静止的完整腰腿反馈并保持三个腿部关节。任务恢复默认四轴姿态后，原动作0以 `position: [0.0]`
  回腰部零位，成功后才检测放置目标 `tray`（缓存键 `tray`）；需要配套更新后的 task_manager。

以后更换槽位，可修改首轮的 `left_pick_y`、`right_pick_y`、`left_place_y`、`right_place_y` 四个 YAML 锚点；第二、三轮分别使用同名加 `_round2`、`_round3` 后缀的锚点；
抓取接近、下降、提起复用抓取Y锚点；放置接近、下降复用放置Y锚点。松爪后MoveP与随后上提使用独立的 `left_place_clear_y`、`right_place_clear_y`（第二、三轮加对应后缀）；修改放置Y时须同步设置 `clear_y = place_y - 0.030`，YAML锚点本身不会计算减法。抓取Y由上式计算，放置及松爪后Y由上表选择。
