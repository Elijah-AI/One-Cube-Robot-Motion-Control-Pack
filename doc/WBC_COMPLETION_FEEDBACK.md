# WBC 完成反馈判据

2026-09-28：修复 WBC 最后一个轨迹点下发后立即返回成功，导致下一步 MoveL 报“手臂未停稳”的问题。

适用于 `arm_id=5/6/7` 的 WBC MovePose，包括 `whole_body_waist_only`。轨迹规划和任务 YAML 不变；末点下发后仍保留手臂与腰腿资源，等待实测反馈满足：

- 参与手臂控制器无错误、无异常状态，且 `low_speed=true`。
- 所有参与手臂及四个腰腿关节的目标位置误差不超过0.01rad。
- 实测关节速度及相邻新反馈位置差分速度均不超过0.01rad/s。
- 上述条件连续保持至少100ms，并获得至少5组新反馈。

手臂读取SDK帧号；腰腿读取带时间戳、序号和驱动状态校验的EtherCAT反馈。重复读取同一帧不会累计有效反馈；序号100ms未前进、非法反向跳变、非有限值或驱动错误均失败。支持SDK帧号正常回绕，仅检查被本次WBC选中的手臂。

等待最多3秒，同时受原Action总超时限制。取消和ROS关闭会结束等待；反馈异常或超时不能返回成功。静态COM检查开启时，等待阶段继续执行原反馈和未参与关节检查。注入的仿真后端需实现 `read_completion_feedback`，默认缺少反馈时失败。

成功日志新增：`WBC measured completion settled after ... s (100 ms stable feedback)`。失败日志区分SDK读取失败、驱动状态异常、反馈不更新和完成等待超时；超时含最后的位置误差、速度及低速标志信息。

这是运控程序修改，需要编译 `motion_control_pkg` 并重启运控节点才生效，单独重启task_manager不能启用新判据。部署不自动重启节点或触发任务；实机衔接效果需运行新运控进程后确认。本修改不解决目标姿态的IK不收敛。
